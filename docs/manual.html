Before you start

A CNC machine may move without warning. Keep the emergency stop within reach, test unfamiliar procedures clear of the workpiece, and never leave the machine unattended.

The app communicates with GRBL 1.1 and FluidNC controllers over Bluetooth, USB OTG or Telnet on Wi-Fi. Before the first job, verify axis directions, units, homing, limits and the work origin.

Connect the machine

  1. Switch on the CNC controller.
  2. Tap the connection icon in the top bar.
  3. Choose Bluetooth, USB OTG or FluidNC Telnet. For Telnet, enter the host/IP and port configured in Settings (normally 23).
  4. Wait for the machine state and coordinates to update.
Bluetooth serial: for GRBL 1.1, an HC-05/HC-06 module normally uses 115200 baud, 8 data bits, no parity and 1 stop bit.
FluidNC: Telnet and the WebUI can coexist on the same network. The controller only needs to be connected to Wi-Fi and reachable from the phone.

If work-position restoration is enabled, the app may offer to reapply the saved position with G10 L20 P0 after reconnecting. Accept only if neither the tool nor the machine has moved.

App layout

The main tabs cover file streaming, jogging, probing, console, CAM, editing and visualization. Machine state, coordinates and connection/reset commands remain at the top.

  • File Sender: load, check and stream G-code; control pause, stop and overrides.
  • Jogging: move X/Y/Z/A and manage work zeros, G54–G57, homing, points and flashlight.
  • Probing: Z probing and tool-length compensation.
  • Console: send commands and read controller responses.
  • CAM: generate simple geometric jobs on the device.

When FluidNC reports its machine name, the app uses it in the header instead of the Bluetooth device name. On small displays the coordinate panel can be hidden in Settings.

Jogging, zeros and points

Jog screen in Demo mode, with simulated coordinates and controls available without a machine.

In step mode, each tap moves by the displayed distance. Continuous mode is identified by the icon for X/Y/A and the icon for Z. Hold an arrow to move and release it to send jog cancel. X/Y/A and Z have separate step modes.

Warning — feature under improvement: use continuous movement with great care. Under some conditions the command might not stop as expected, causing the machine to jam or reach a limit. Test it initially at low speed, keep the travel path clear and be ready to use the emergency stop.
Before using “go to zero”, make sure the path is clear: it uses a rapid move. If Z must move too, first raise the tool to a safe height.

Volume keys: while a job is in Run they pause it; in Hold they resume it. In every other state they immediately send jog cancel, without first checking whether a jog is active.

Volume-key control still depends on the phone and its connection. It is a useful software stop, not a substitute for a physical emergency-stop switch that removes machine power.

The bell unlocks an alarm ($X), the home icon starts homing after confirmation, and the light bulb controls the phone flashlight. Four custom buttons can each hold multiple commands and separate short/long actions.

Get point stores each reading as a plain X/Y/Z row in points.txt, with no header and no three-point limit. It can therefore be used for manual surveying or as the CAM polyline source.

Load and run a G-code file

File Sender in Demo mode with a sample file and active controls.
  1. Tap the file selector and choose the app folder, Android system picker or, when available, the FluidNC SD card.
  2. Check the origin, Z height, tool, workholding and Idle state.
  3. Open the visualizer and inspect the toolpath.
  4. Press Play, review the safety summary and confirm.
  5. Use pause/resume during the job; Stop ends the job.

Files on the FluidNC SD card

With a FluidNC connection you can browse the controller SD card and start a file with $SD/Run. FluidNC reads the job directly, so execution is independent of phone streaming; the app remains connected for status and controls. Keep the network stable so you retain remote control.

Spindle control

In Idle, the spindle button starts with M3 plus the configured manual S value—which is also required for FluidNC 0–10 V output—and stops with M5. Long-press to change S without starting. During Hold it uses the real-time spindle stop/restore command; during Run, pause first.

Run from line

Long-press Play, enter the line number shown in the editor and follow the procedure. The app reconstructs the preceding modal state—including units, plane, coordinate system, distance mode, feed, spindle and coolant—then offers automatic positioning at a safe Z or manual placement.

Run from line: always verify the physical position, work origin and tool. The app warns before restarting a spindle or coolant that was active at the selected line.

When enabled, Z-plunge detection checks the file during loading and warns about unusually deep, steep descents. It is a safety aid, not a substitute for inspecting the toolpath.

Editor and visualizer

G-code editor with search, syntax highlighting and save.

The editor's line numbers match “Run from line”. The OpenGL visualizer supports drag, pinch zoom, reset and fit-to-view. During streaming, completed toolpath segments are dimmed.

The sample toolpath displayed in the visualizer.

Command console

Console for controller responses and manual commands.

Type a command in the bottom field and press Send. Verbose output shows additional information. Use the console only when you understand the GRBL or FluidNC command being sent.

Z probing and tool length offset

Probe parameters, automatic Z adjustment and tool-length compensation.
  1. Set feed rate, plate thickness and maximum probing distance.
  2. Connect the probe circuit and test contact before movement.
  3. Start Probe and confirm.
  4. For a tool change, probe with the first tool, change it without losing the reference, then use Probe + TLO.

G49 cancels tool-length compensation.

Three-point auto-leveling

  1. Load the G-code in File Sender.
  2. Move to the first location by probing or manual positioning, then short-tap Leveling. The app creates levelingpoints.txt and records it.
  3. Follow the prompts and tap Leveling again at the second and third non-collinear points.
  4. After point three, check the summary of file, units, work coordinate system and recorded coordinates.
  5. Confirm generation, then inspect the new _leveled file in the visualizer.

If three points already exist, the app asks whether to reuse them or delete them and restart. Long-press Leveling to delete levelingpoints.txt after confirmation. The general-purpose points.txt remains independent.

Leveling requires millimetres (G21), the same work coordinate system and three non-collinear points. G2/G3 arcs are rejected: configure the CAM to linearize them into G1 segments. The file must also establish XY before its first absolute Z move.

On-the-fly CAM

Quick geometric toolpath generation inside the app.

The CAM tab generates lines, circles and rectangles with multiple Z passes. Set Point 1, Point 2, job type, feed, total depth, depth per pass, clearance height and any tool/step-over values. “Write job file” saves job.nc and loads it in File Sender.

Polyline engraving from points.txt

This mode joins every saved point in file order. At least two valid rows are required: X, Y and Z from the first point define the reference; only X and Y are used from later points, whose Z values are ignored. Set feed, total depth, depth per pass and safe height as for other jobs. Alternating passes run forwards and backwards to avoid unnecessary repositioning.

Before generation, the summary shows point count, reference Z, safe Z, final Z, pass count and effective step. Coordinates are currently interpreted as millimetres and must use one work coordinate system. A malformed row is reported with its exact line number.

Always inspect the generated file and perform the first test above the stock.

File transfer and browser control

Browser interface reconstructed from the app server: job status, pause/stop, overrides, upload and G-code file management.
  1. Open Settings → File HTTP server.
  2. Set a password of at least four characters and enable the server.
  3. Connect the PC and Android device to the same trusted Wi-Fi network.
  4. Open the address shown in the notification; username: grbl.

The page can upload/download G-code, show job state and progress, pause or stop a job, change overrides and make the host device ring. Its header also shows the machine name reported by FluidNC and the phone battery level, with a low-charge warning.

The server is intended for a trusted local network. Use a strong password and disable it when it is not needed.
